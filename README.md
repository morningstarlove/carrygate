# CARRYGATE

매일 자동으로 시장을 확인해서 **판단 근거만 기록하는 장치**다.
주문은 넣지 않는다. 거래소 API 키도 쓰지 않는다. 읽기 전용이다.

**한눈에 보기:** 통합 현황판 https://claude.ai/artifact/T2RK2MQX3uZwwbjVhPMZSH (GitHub 연결로 이 저장소의 결과 파일을 직접 읽는다. 소유자만 열 수 있다.)

## 1. 신호등 (`status.json`)

비트코인 등 6개 코인의 **최근 200일 평균 가격**과 현재 가격을 비교한다.

- 현재 가격이 평균보다 **위** → **초록(열림)**. 시장 분위기 정상.
- 현재 가격이 평균보다 **아래** → **빨강(닫힘)**. 손대지 않는 게 낫다.
- 3개월 고점 대비 30% 넘게 빠졌으면 → **급락 표시**. 무조건 중단.

이건 "뭘 사라"가 아니라 **"언제 아예 손대지 말아야 하나"**를 알려주는 장치다.

## 2. 이자율 (`funding.json`)

### 무슨 전략인가

**양쪽에 동시에 걸고 이자만 받는 방법**이다.

코인 시장에는 두 종류의 시장이 있다.
- **현물 시장** — 실제 코인을 사서 보유하는 곳
- **무기한선물 시장** — 코인 없이 "오른다/내린다"에만 돈을 거는 곳

선물 시장에는 규칙이 하나 있다.
**"오른다"에 건 사람이 많으면, 그쪽이 "내린다"에 건 쪽에 몇 시간마다 돈을 준다.**
양쪽 인원 균형을 맞추려고 거래소가 만든 규칙이고, 이 돈을 **펀딩비**라고 부른다.

그래서 이렇게 한다.

| 하는 일 | 가격이 오르면 | 가격이 내리면 |
|---|---|---|
| 현물로 1개 산다 | +100만원 | −100만원 |
| 선물에서 "내린다"에 1개만큼 건다 | −100만원 | +100만원 |
| **합계** | **0원** | **0원** |

**가격이 오르든 내리든 원금은 그대로**고, 위 규칙 때문에 **몇 시간마다 이자만 들어온다.**
가격을 맞힐 필요가 없다. 그래서 "예측이 틀렸다"는 위험 자체가 없다.

### 이 파일이 하는 일

거래소 5곳(바이낸스 / 바이비트 / OKX / 게이트 / 하이퍼리퀴드)에서
6개 코인의 펀딩비를 읽어, **연 몇 %인지**로 바꿔 한 줄로 보여준다.

거래소마다 이자 주는 주기가 다르다(8시간마다, 1시간마다 등).
그래서 주기를 각 거래소에서 직접 읽어와 계산한다. 그냥 곱하면 틀린다.

모든 거래소에서 **최근 7일 평균**을 계산한다. 한 번 찍힌 값은 튀기 때문에, 평균이 있으면 그걸로 판단한다.
바이낸스·바이비트는 미국 서버에서 막혀 있어 **CoinGecko 파생상품 API**(현재값, 일별 표본 5개부터 7일 평균)로 받고,
한국 PC 의 중계기(`kr_relay.py`, 선택)가 올린 파일이 있으면 그것(실제 정산 이력)을 우선 쓴다.

### 판정 규칙

| 상태 | 조건 (**수수료 뺀 순수익** 기준) | 뜻 |
|---|---|---|
| **중단** | 신호등에 급락 표시 | 시장이 흔들리는 중. 거래소 자체가 위험. 들어가지 않는다 |
| **진입 가능** | 순 연 8% 이상 | 수수료 빼고도 남는다. 들어갈 만하다 |
| **대기** | 순 연 2 ~ 8% | 새로 들어가진 않는다. 이미 들고 있으면 유지 |
| **청산** | 순 연 2% 미만 | 이자가 예금만도 못하다. 정리한다 |

들어가는 기준(8%)과 나오는 기준(2%)을 **다르게 둔 이유**는,
기준이 하나면 그 언저리에서 들어갔다 나왔다를 반복하며 수수료만 나가기 때문이다.

### 수수료를 뺀 뒤에 판단한다

펀딩비만 보면 실제로 손에 쥐는 돈을 부풀려 보게 된다.
캐리는 **진입에 2번**(현물 사기 + 선물 걸기), **청산에 2번**, 총 4번 수수료를 낸다.

수수료는 거래소마다 다르게 적용한다 (30일 보유 기준).

| 거래소 | 수수료 근거 | 연 부담 |
|---|---|---|
| **하이퍼리퀴드** | **매일 API에서 실제 수수료표를 받아온다** (기본 등급) | 현물이 있으면 약 2.8%, 없으면 약 3.5% |
| OKX · 게이트 등 | 보수적 기본 가정 (현물 0.10% + 선물 0.05%) | 3.65% |

하이퍼리퀴드에 그 코인의 **현물이 없으면**, 현물은 다른 거래소에서 사야 하므로
현물 수수료는 기본 가정으로 계산한다. 어느 코인이 하이퍼리퀴드 현물에 있는지도
매일 API로 확인해 `funding.json` 에 남긴다.

> 하이퍼리퀴드 API가 실패한 날은 공식 문서의 기본 등급 값(선물 0.045%, 현물 0.070%)으로
> 대신 계산하고, 그 사실을 결과에 표시한다. 결과에는 총수익과 순수익이 모두 남는다.

### 스스로 검산한다

매일 실행 끝에 `selfcheck.py` 가 돌아, **저장된 수치를 원본 펀딩비에서 처음부터
다시 계산해** 일치하는지 대조한다. 기록 날짜가 중복되거나 빠졌는지, 거래소 수집이
몇 곳이나 성공했는지도 함께 본다. 어긋나면 그날 실행이 **빨간불**로 표시된다.

## 3. 초단타 성적표 (`scalp.json`)

### 무엇을 하나

**미리 정해 둔 초단타 규칙 7가지 + 기준선 1가지**를 매일 **어제 하루치**에 그대로 적용해 보고,
수수료와 호가 차이를 뺀 순수익을 기록한다. 1분봉을 받아 **1분·5분·15분봉** 세 가지로 묶어
같은 규칙을 적용하므로 "어느 시간 단위부터 비용을 넘는가"도 같이 보인다.
규칙은 코드에 고정돼 있어 매일 **새 데이터로 순방향 검증**이 된다. 과거 데이터에 맞춰
규칙을 고치는 일(과최적화)이 원천적으로 생기지 않는다.

| 규칙 | 체결 | 요지 | 최대 보유 |
|---|---|---|---|
| 평균회귀 | 시장가 | 20봉 평균에서 2σ 넘게 벗어나면 되돌아온다고 보고 반대로 진입 | 30봉 |
| 평균회귀 지정가 | 지정가 | 같은 신호를 지정가로. 가격이 주문가를 **지나쳐야** 체결, 3봉 미체결 시 취소 | 30봉 |
| 돌파 | 시장가 | 20봉 최고가를 넘으면 추세 시작으로 보고 따라 진입 | 60봉 |
| 거래량 급증 추종 | 시장가 | 거래량 3배 + 한쪽 끝 마감이면 그 방향으로 5봉 | 5봉 |
| VWAP 이탈 되돌림 | 시장가 | 60봉 거래량가중평균가에서 1.5σ 벗어나면 반대로 진입 | 60봉 |
| VWAP 되돌림 지정가 | 지정가 | 같은 신호를 지정가로 (위와 같은 체결 규칙) | 60봉 |
| 변동성 돌파 | 시장가 | 당일(UTC) 시가에서 전날 고저 폭의 절반만큼 오르면 진입, 그날 끝에 청산 (하루 1회 성격) | 당일 |
| 기준선 | 시장가 | 규칙 없이 10봉마다 사서 5봉 뒤 팔기 (규칙에 정보가 있는지 비교용) | 5봉 |

시장: 업비트(현물, 롱만) · 하이퍼리퀴드(선물, 롱·숏) · OKX(선물, 롱·숏) × 6개 코인 × 3개 시간 단위.

### 비용을 뺀 뒤에 판단한다 (초단타에서는 이게 전부다)

체결 1회 비용은 **시장가 = 수수료 + 호가 차이의 절반**, **지정가 = 수수료만**이다.
업비트는 0.05%(시장가·지정가 동일), 하이퍼리퀴드는 시장가 0.045% / 지정가 0.015%,
OKX 는 시장가 0.05% / 지정가 0.02%. 호가 폭은 그날 데이터에서 가격이 움직인 최소 단위로 추정한다.

지정가는 수수료가 싸지만 **체결이 안 될 수 있다.** 그래서 지정가 규칙은 "다음 봉의 저가(매수)·고가(매도)가
주문가를 지나쳤을 때만 체결"로 보수적으로 계산하고, 3봉 안에 체결되지 않으면 진입은 취소, 청산은
시장가로 강제한다. 체결된 쪽이 지정가인지 시장가인지 건수(`maker_sides` / `taker_sides`)를 남기므로
검산기가 비용을 그대로 다시 계산할 수 있다.

`scalp.json` 의 **비용 문턱** 표는 "이 시장에서 1·5·15·30·60분 뒤 가격이 평균 얼마나 움직이나"와
"비용을 내고도 본전이 되려면 승률이 몇 % 필요한가"를 보여준다.
**필요 승률이 100% 를 넘으면 그 시간 단위 초단타는 아무리 잘 맞혀도 비용을 못 넘는다.**

### 판정 규칙

하루 결과만으로는 판단하지 않는다. `scalp_history.jsonl` 에 매일 한 줄씩 쌓고,
`python scalp.py --report` 로 누적 성적을 본다.

| 후보 조건 (모두 충족) | 뜻 |
|---|---|
| 기록 7일 이상 | 하루짜리 우연을 거른다 |
| 누적 순수익(시장가) 플러스 | 비용을 빼고 남았다 |
| 플러스 일수 60% 이상 | 하루 대박이 아니라 꾸준하다 |
| 같은 시장의 기준선보다 낫다 | 규칙에 실제 정보가 있다 |

후보가 나와도 실전 전에 **소액으로 체결 가능 여부를 먼저 확인**해야 한다.
시장가 규칙은 다음 봉 시가 체결, 지정가 규칙은 "지나쳐야 체결" 가정이라 실제 체결과 다를 수 있다.

## 4. 초단타 보조 연구 (`research.json`, `orderbook.json`)

규칙 검증과 별개로, **새 규칙을 설계할 때 근거가 될 사실**을 매일 계산해 쌓는다.
여기서 나온 숫자로 기존 규칙을 고치지는 않는다.

| 항목 | 질문 | 계산 |
|---|---|---|
| A1 시간대 | 하루 중 어느 시간에 15분 변동폭이 비용을 넘나 | 한국시간 시간대별 본전 승률 |
| A2 펀딩 정산 | 펀딩비가 클 때 정산 직전·직후 가격이 한쪽으로 움직이나 | 정산 15분 전·후 수익률 × 펀딩 부호 |
| B 선행·후행 | 한 거래소의 1분 움직임이 다른 거래소의 다음 1분을 예측하나 | 1분 수익률 상관, 큰 움직임 따라가기 bp |
| C 호가창 | 매수·매도 잔량 불균형이 다음 1분을 맞히나. 호가 폭이 지정가 수수료보다 넓나 | 매일 22시부터 5시간 30분, 10초 간격 표본 |

A·B 는 매일 아침 실행(`scalp_research.py`)에 포함되고, C 는 별도 워크플로(`orderbook.py`)가
밤에 돈다. 원본 호가 표본은 저장소에 넣지 않고 실행 산출물로 7일만 보관한다.
`python scalp_research.py --report` / `python orderbook.py --report` 로 누적을 본다.

**주의 (ETF 자료):** 가격은 분할만 조정되고 **배당은 반영되지 않았다.** 채권·현금 ETF(AGG·BIL·TLT·IEF)는
배당이 수익의 대부분이라 실제보다 낮게 나온다. 전략 간 **상대 비교**와 낙폭 비교에는 쓸 수 있지만
절대 수익률은 1~3%p 낮게 보면 된다.

**매크로 달력**은 Actions 에서 받을 수 없어 이 저장소에 파일로 둔다(`data/macro_calendar.json`).
마지막 이벤트가 2주 안이면 `macro.json` 에 `calendar_stale: true` 로 표시되며, 매달 갱신한다.

## 6. 한국 주식 — 업종 동조 + 패턴 돌파 (마일스톤 12)

SNS 에 돌던 5문장("거래대금 상위 100 → 같은 업종끼리 묶기 → 같이 오른 업종 → 박스권·삼각수렴·깃발·컵앤핸들이면 → 매수")을
**기계가 매일 똑같이 판정하는 숫자 규칙**으로 바꾼 것이다. 설계서 `docs/KR_SECTOR_BREAKOUT_PLAN.md`. 주문은 넣지 않는다.

| 단계 | 파일 | 하는 일 |
|---|---|---|
| 1~3 | `kr_universe.py` → `kr_sector.json` | 거래대금 상위 100(ETF·스팩 제외)을 업종(industry)으로 묶고, 3종목 이상·60% 이상 상승·중앙값 +2%(또는 5일 +5%)면 **동조** |
| 4 | `patterns.py` | 일봉으로 4패턴 판정. 공통: 종가 > 저항선, 거래량 20일 평균의 1.5배, 20일선 위, 거래대금 100억+, 상한가 제외 |
| 5 | `kr_breakout.py` → `kr_breakout.json` | 동조 업종 안의 돌파 종목을 **다음날 시가** 종이매매. 손절 −7%(또는 패턴 하단), 10일 최저가 이탈·20일 보유 청산, 1% 위험, 최대 5종목 |
| 일봉 | `kr_ohlcv.py` | 야후 → 네이버 순서로 일봉 수집 (네이버는 시간외 거래가 섞여 2순위) |

세 변형을 나란히 기록한다: `base`(동조 필요) / `no_sector`(패턴만, **업종 동조가 실제로 보태는 게 있는지 보는 대조군**) / `hold_10`.
백테스트(`--backtest`, 3년, 지금 거래대금 상위 300 종목)는 **생존 편향**이 있어 실제보다 좋게 나올 수 있다. 진짜 시험은 규칙 고정일
이후 매일 쌓이는 **순방향 기록**이다. 워크플로 **KR sector breakout** 이 평일 15:45 KST(장 마감 뒤)에 돈다.

## 7. 언제 어떻게 돌아가나

GitHub Actions가 **매일 한국시간 오전 9시 18분**에 자동 실행한다.
결과는 `status.json` / `funding.json` / `scalp.json` / `research.json` 에 저장되고 저장소에 자동으로 커밋된다.
과거 기록은 `history.jsonl` / `funding_history.jsonl` / `scalp_history.jsonl` / `research_history.jsonl` 에 하루 한 줄씩 쌓인다.
호가창 워크플로(**CARRYGATE orderbook**)는 매일 한국시간 22시에 시작해 `orderbook.json` / `orderbook_history.jsonl` 을 남긴다.
한국 주식 워크플로(**KR sector breakout**)는 평일 한국시간 15시 45분에 `kr_sector.json` / `kr_breakout.json` 과 각 이력을 남긴다.

수동으로 돌려보려면 GitHub 저장소 → **Actions** 탭 → **CARRYGATE daily**
→ **Run workflow**. 이때 `dry_run` 을 체크하면 **결과만 보고 저장은 하지 않는다.**
