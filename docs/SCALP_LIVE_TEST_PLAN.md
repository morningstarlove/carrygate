## 2. 규칙 그대로 옮기기 (코드가 실제로 하는 일)

종이매매 코드(`scalp.py`)가 하는 것을 사람 말로 옮기면 아래와 같다. 실제 주문기도 **이 순서를 한 글자도 바꾸지 않고** 따른다.

1. **봉:** OKX 1분봉을 받아 15분봉으로 묶는다(00분·15분·30분·45분 UTC 경계). 신호는 **15분봉이 끝난 직후** 그 봉의 종가로만 계산한다.
2. **VWAP 거리:** 최근 60개 15분봉(15시간)의 거래량가중평균가와, 같은 60봉 종가의 표준편차(σ)를 구한다. 거리 = (종가 − VWAP) ÷ σ.
3. **진입 신호:** 거리가 **−1.5 이하면 롱**, **+1.5 이상이면 숏**. 포지션이 있거나 미체결 주문이 있으면 새 신호는 무시한다.
4. **진입 주문:** 신호 봉의 **종가**에 지정가(메이커, post-only). 다음 **3봉(45분)** 안에 가격이 주문가를 **지나쳐야** 체결된 것으로 본다. 3봉 안에 안 되면 **취소**.
5. **청산 신호:** 보유 중 봉 종가의 거리가 롱이면 0 이상, 숏이면 0 이하로 **돌아오면** 청산.
6. **청산 주문:** 신호 봉 종가에 지정가. **3봉 안에 안 체결되면 시장가**로 청산. 보유가 **60봉(15시간)**에 닿으면 무조건 시장가 청산.
7. **하루 경계:** 규칙에 날짜 개념은 없다. 밤에도 돈다(그래서 24시간 컴퓨터가 필요하다).

**종이매매와 실제가 다를 수 있는 지점(이 시험이 재려는 것):**
- 4번 "지나쳐야 체결"은 보수적 가정이다. 실제로는 주문가에 **닿기만 해도** 체결될 수 있고(유리), 반대로 호가 줄이 길어 지나쳐도 안 체결될 수 있다(불리).
- 지정가 post-only 는 주문 순간 가격이 이미 지나갔으면 거래소가 **거부**한다. 종이매매엔 이 경우가 없다.
- 6번 시장가 청산의 실제 비용(수수료 0.05% + 호가 폭)과 종이매매 가정(수수료 + 1틱의 절반)의 차이.

## 3. 준비 (하루)

1. **OKX 계정** — 본인 인증 완료, 선물(무기한) 거래 활성화. 선물 계정에 **USDT 250** 이체.
2. **API 키 만들기** — OKX 웹 → 프로필 → API → 키 생성.
   - 권한: **거래(Trade)·읽기(Read)만.** 출금(Withdraw) 은 **절대 끈다.**
   - **IP 화이트리스트**에 주문기를 돌릴 컴퓨터의 공인 IP 만 넣는다(집 PC 면 집 IP).
   - API 키·시크릿·패스프레이즈 세 값은 **주문기 저장소의 GitHub Secrets 또는 그 컴퓨터의 환경 변수**에만 둔다. 채팅·메모·이 저장소에는 **절대 적지 않는다.**
3. **거래 설정** — XRP-USDT-SWAP, **격리(Isolated) 마진, 레버리지 1배**, 포지션 모드 **단방향(net)**. 이 셋은 주문기가 시작할 때 다시 확인하고 다르면 멈춘다.
4. **주문기 컴퓨터** — 4절의 (가)·(나) 중 하나. 전원·인터넷이 14일 동안 끊기지 않아야 한다.
5. **시작 전 24시간 "주문 없는 모드(dry)"** — 신호와 가상 주문만 기록해 종이매매와 **똑같은 신호가 나오는지** 확인한다. 하나라도 다르면 시작하지 않는다.

## 4. 주문기 (별도 저장소 `carrygate-exec`)

**이 저장소(carrygate)에는 주문 코드도, 키도 두지 않는다.** 주문기는 새 저장소 하나로 만든다.

| 구성 | 내용 |
|---|---|
| 신호 계산 | `scalp.py` 를 **커밋 해시로 고정해 복사**해 와서 그 안의 `Ctx`·`e_vwap`·`x_vwap`·`limit_filled`·`backtest` 를 그대로 호출한다. 코드가 같으니 신호가 같다 |
| 자료 | OKX 공개 API 1분봉(키 불필요). 15분봉 경계마다 최근 61봉(약 16시간)을 다시 받아 계산한다 |
| 주문 | OKX 거래 API. 지정가는 **post-only**. 주문·취소·체결 응답을 전부 `exec_log.jsonl` 한 줄씩 저장 |
| 종이매매 동시 기록 | 같은 봉으로 `backtest()` 를 돌려 "종이매매였다면" 의 진입·청산을 `paper_log.jsonl` 에 함께 남긴다. **비교의 기준선** |

| 실행 환경 | **(가) 집 PC** (Windows 작업 스케줄러로 부팅 시 자동 실행, 무료) **(나) 월 5달러 안팎 VPS** (24시간 보장). 1차는 (가), 전원·네트워크로 하루라도 끊기면 (나)로 |
| 실행 주기 | 15분봉 경계 **+10초**에 한 번. 매번 ① 미체결 주문 상태 확인 ② 포지션 확인 ③ 신호 계산 ④ 주문/취소 |

### 상태 기계와 재시작 복구 (2026-10-10 추가, `docs/AI_FRAMEWORKS_REVIEW.md` 3절 ①. 합격선·규칙 변경 없음)

집 PC 재부팅이나 프로그램 중단 뒤에도 "어느 단계였는지"를 알고 이어서 돌기 위해, 주문기는 상태 다섯 개만 가진다.

| 상태 | 뜻 | 다음 상태 |
|---|---|---|
| `IDLE` | 포지션·미체결 없음 | 진입 신호 → `ENTRY_PENDING` |
| `ENTRY_PENDING` | 진입 지정가 대기(최대 3봉) | 체결 → `IN_POSITION`, 3봉 경과 → 취소 후 `IDLE` |
| `IN_POSITION` | 1계약 보유 | 청산 신호 → `EXIT_PENDING`, 60봉 → 시장가 청산 후 `IDLE` |
| `EXIT_PENDING` | 청산 지정가 대기(최대 3봉) | 체결 → `IDLE`, 3봉 경과 → 시장가 청산 후 `IDLE` |
| `HALTED` | 안전장치 발동 | 사람이 확인하기 전엔 안 움직인다 |

- 매 실행 끝에 `state.json` 에 {상태, 주문 ID, 수량, 진입가, 마지막 봉 시각} 을 쓴다.
- 시작할 때 `state.json` 과 **거래소의 실제 포지션·미체결 주문**을 대조한다. 다르면 거래소 쪽을 믿고 `HALTED`. 모르는 상태로는 주문하지 않는다.
- 거래소 응답(주문 ID·체결 수량·체결가·포지션)은 쓰기 전에 타입·범위를 검사하고, 어긋나면 주문하지 않고 `HALTED`(같은 문서 3절 ③).
- 상태 전이는 전부 `exec_log.jsonl` 한 줄("어느 상태에서 어떤 입력으로 어디로").

## 5. 운영 중 매일 할 일 (5분)

1. 현황판 "체결 시험" 카드(또는 `compare.json`)에서 **어제 체결률·실제 비용·종이 대비 순수익**을 본다.
2. OKX 앱에서 포지션이 **0개 또는 1개(1계약)** 인지, 미체결 주문이 **1개 이하**인지 본다. 다르면 `STOP` 파일을 만들고 알린다.
3. 안전장치 알림이 왔으면 그날은 손대지 않고 저에게 기록을 보낸다. **규칙·문턱값은 시험 중 바꾸지 않는다.**

- 체결률·비용만 미달 → 규칙은 살려 두고 **주문 방식만** 바꾸는 제안(예: 주문가를 1틱 안쪽으로)을 `proposals.md` 에 올린다. 그건 새 시험이다.
- 종이매매 자체가 14일 동안 마이너스 → 시험은 유효하나 규칙이 탈락. 초단타는 마일스톤 5 "탈락 시 대안"으로.
- 종이매매가 플러스인데 실제가 마이너스이고 비용·체결률은 통과 → 표본 부족. 2주 **연장 1회만**.

## 7. 위험 (수익보다 중요)

- **24시간 컴퓨터가 멈추면 포지션이 방치된다.** 최대 보유 15시간 규칙이 안 돈다. → 안전장치 "연결 끊김"은 주문기 쪽 기준이라 컴퓨터 자체가 꺼지면 소용없다. 대책: OKX 앱 알림 켜 두고, 매일 2번(아침·밤) 포지션 확인. 1차 (가) 집 PC 에서 하루라도 꺼지면 (나) VPS 로.
- **급변 시 시장가 청산 비용.** 15분봉 규칙의 손절은 "60봉 뒤 시장가"뿐이다. 10/2 고용 발표 같은 날 종이매매 하루 −3%. 1계약 140달러면 4달러. 이 금액을 잃어도 되는 돈으로만.
- **API 키 유출.** 출금 권한 없음 + IP 제한으로 돈은 못 빼 가지만 주문은 낼 수 있다. 키는 시험 끝나면 **삭제**한다.
- **OKX 가 한국에서 막힐 가능성.** 2026-10 현재 OKX 는 한국 IP 에서 접속·거래가 된다(이 저장소의 매일 수집이 미국 서버에서도 된다). 막히면 하이퍼리퀴드 XRP(같은 규칙, 10일 후보엔 없음)로 바꾸되 그건 새 시험이다.
- **1계약 단위의 거침.** 금액 조절이 안 된다. 2차에서 금액을 늘릴 때도 계약 수(1→2→4)로만 늘어난다.
