# 캐리 소액 실전 설계서 (1차)

> 목적은 **돈을 버는 것이 아니라 확인하는 것**이다. 14일 동안 기록만 해 온 "현물 매수 + 선물 숏 → 펀딩비 수취"가
> 실제 계좌에서도 그 숫자대로 들어오는지, 숨은 비용이 얼마인지, 혼자서 운영할 수 있는 절차인지를 소액으로 확인한다.
> 이 문서는 코딩·금융 지식이 없는 사람이 그대로 따라 할 수 있게 쓴다.

**작성:** 2026-10-01 · **근거 자료:** `funding_history.jsonl` 14일치, `funding.json` (하이퍼리퀴드 수수료 API 실측)

## 1. 결정 사항 (왜 이렇게 하나)

| 항목 | 결정 | 이유 (실측 근거) |
|---|---|---|
| 거래소 | **하이퍼리퀴드 한 곳** | 14일 기록에서 6개 코인 모두 1위. 현물·선물이 한 계정에 있어 자금 이동이 없다 |
| 코인 | **ETH** (현물 UETH + 선물 ETH 숏) | 하이퍼리퀴드에 현물이 있는 코인은 BTC·ETH 둘뿐. ETH 는 순 연 8.2%(문턱 8% 충족), BTC 는 5.4%(미달). DOGE(10.7%)는 현물을 다른 거래소에서 사야 해서 **두 거래소 운용** — 1차에서는 제외 |
| 금액 | **총 150 USDC 안팎 (약 20만원)** | 하이퍼리퀴드 최소 주문 10달러. 현물 70 + 선물 증거금 70 + 여유 10. 잃어도 되는 돈이어야 한다 |
| 기간 | **14일** | 펀딩은 1시간마다 정산되므로 14일이면 336회 수취. 평균을 말할 수 있는 최소 표본 |
| 레버리지 | **1배** (증거금 = 포지션 명목) | 가격이 두 배가 되어도 강제청산이 안 나는 거리. 수익률을 올리려고 레버리지를 쓰지 않는다 |
| 성공 기준 | 실현 순 연수익이 **예측의 70% 이상** | `live_monitor.py` 가 매일 "실현 ÷ 예측" 을 기록한다. 14일 뒤 0.7 이상이면 2차(금액 확대)로 |

**예상 수익(14일):** 70 USDC × 8.2% × 14/365 ≈ **0.22 USDC(약 300원)**. 수수료 약 0.1 USDC 를 빼면 **0.1 USDC 남는다.**
수익이 목적이 아니라는 뜻이 이 숫자에 있다. 확인하려는 것은 "비율"이다.

## 2. 준비 (하루)

하이퍼리퀴드는 거래소 계정이 아니라 **지갑**으로 쓴다. 한국 거래소에서 USDC 를 사서 지갑으로 보내고, 그 지갑으로 하이퍼리퀴드에 접속한다.

1. **지갑 만들기** — 메타마스크(MetaMask) 브라우저 확장 또는 앱. 복구 문구 12단어를 **종이에** 적어 보관. 사진·메모앱 금지.
2. **아비트럼(Arbitrum) 네트워크 추가** — 메타마스크 네트워크 목록에서 Arbitrum One 선택.
3. **USDC 구입** — 업비트 KRW 마켓에서 USDC 약 160개 매수(수수료·가스 여유 포함).
4. **출금** — 업비트 → 내 메타마스크 주소로 USDC 출금, **네트워크는 반드시 Arbitrum** 선택. 처음에는 **10 USDC 만 시험 송금**해서 도착을 확인한 뒤 나머지를 보낸다.
   - 업비트는 개인 지갑 출금 전 **지갑 등록·본인 확인 절차**가 있다(특정금융정보법). 앱 안내를 따른다. 금액에 따라 24시간 대기가 걸릴 수 있다.
5. **하이퍼리퀴드 입금** — app.hyperliquid.xyz 접속 → 지갑 연결 → Deposit → Arbitrum USDC 입금. 몇 분 안에 잔고에 보인다.
6. **지갑 주소를 저장소에 등록** — 아래 "감시 자동화" 참고. 주소는 공개 정보라 저장소에 넣어도 된다(**복구 문구·비밀키는 절대 아니다**).

> **확인 필요(사실 확인 전):** 업비트 개인 지갑 출금 가능 여부와 한도는 계정 등급에 따라 다르다. 출금 전 업비트 고객센터 공지를 확인한다.

## 3. 진입 절차 (30분)

같은 수량을 **거의 동시에** 사고 팔아야 가격 변동 위험이 없다. 순서는 현물 먼저.

| 단계 | 할 일 | 확인 |
|---|---|---|
| 1 | 하이퍼리퀴드 **Spot** 탭에서 `UETH/USDC` 를 **70 USDC 어치 시장가 매수** | 체결된 UETH 수량을 메모 (예: 0.0200) |
| 2 | **Perp** 탭 `ETH` 에서 **같은 수량을 시장가 숏** (Sell). 레버리지 1배, 증거금 모드 Isolated(격리) | 체결 수량이 1단계와 같은지 확인 |
| 3 | 포지션 화면에서 **강제청산 가격(Liq. Price)** 확인 | 현재가의 **1.8배 이상**이어야 한다. 아니면 증거금 추가 |
| 4 | 현물 UETH 수량 = 선물 숏 수량인지 재확인 | 차이가 1% 넘으면 작은 쪽에 맞춰 조정 |

수수료(실측 기본 등급): 현물 0.07% + 선물 0.045% = 진입에 약 **0.08 USDC**. 청산 때 한 번 더.

## 4. 운영 중 매일 할 일 (5분)

- 자동: 매일 09:18 `live_monitor.py` 가 지갑 주소로 포지션·펀딩 수취·수수료를 조회해 `live.json` 에 기록하고, 매일 10시 점검 루틴이 **경고가 있을 때만** 알린다.
- 수동: 하이퍼리퀴드 앱에서 포지션이 살아 있는지 한 번 본다.

자동으로 잡는 경고 3가지:

| 경고 | 뜻 | 조치 |
|---|---|---|
| 현물·선물 수량 차이 5% 초과 | 델타 중립이 깨졌다 (한쪽만 체결됐거나 일부 청산) | 작은 쪽에 맞춰 수량 조정 |
| 강제청산 가격까지 30% 미만 | 가격이 급등해 증거금이 모자란다 | 증거금 추가 또는 양쪽 동시 청산 |
| 예측 순 연수익 < 2% (7일 평균) | 이자가 예금만도 못하다 | 양쪽 동시 청산(5절) |

## 5. 청산 절차 (14일 뒤 또는 경고 시)

1. Perp 탭에서 ETH 숏을 **시장가로 전량 청산**(Close).
2. Spot 탭에서 UETH 를 **시장가로 전량 매도**.
3. 두 체결 시각 차이가 1분 안이면 가격 변동 위험은 무시할 수 있다.
4. `live_monitor.py --report` 로 14일 성적표를 확인하고 아래 6절 판정표를 채운다.

## 8. 감시 자동화 (이미 준비됨)

`data/live_wallet.json` 파일을 만들어 넣으면 다음 날부터 자동으로 기록된다.

```json
{"address": "0x여기에_메타마스크_주소", "started_utc": "2026-10-03", "coin": "ETH",
 "note": "소액 실전 1차 — ETH 현물 UETH + 선물 숏, 150 USDC"}
```

- 주소는 공개 정보다. **비밀키·복구 문구는 어디에도 넣지 않는다.** 이 저장소는 주문을 넣을 수 없다.
- 파일을 넣는 방법: GitHub 저장소 → `data` 폴더 → Add file → Create new file → 이름 `live_wallet.json` → 위 내용 붙여넣기 → Commit.
  또는 저에게 주소를 알려주면 넣어 드린다.
- 기록되는 것: 현물·선물 수량 일치, 펀딩 수취 합계, 수수료, 실현 연환산, 예측 대비 비율, 강제청산 거리, 경고.
