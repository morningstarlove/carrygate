# AI 에이전트 프레임워크 5종 검토 — 우리가 가져갈 것과 안 가져갈 것

> 2026-10-10 작성. 대상: LangGraph · CrewAI · PydanticAI · Agno · Mastra (SNS 카드, 별 수는 카드 기준).
> 코딩 지식 없이 읽을 수 있게 썼다. 판단 근거는 이 저장소의 기록(`HANDOVER.md`, `docs/PHIL_ANALYSIS.md`, `proposals.md`)이다.
> 모든 세션이 지키도록 결론은 루트 `CLAUDE.md` 에 요약해 두었다.

## 0. 한 줄 결론

**다섯 개 모두 지금은 설치하지 않는다. 대신 각 도구의 "방법" 네 가지를 우리 방식(순수 파이썬·규칙 고정·순방향 검증)에 맞게 가져온다.**

이유 세 줄:
1. 이 다섯은 전부 **"AI 모델이 매 단계 판단하는 앱"을 만드는 도구**다. 우리는 **매매 판단에 AI 를 쓰지 않는다** — 규칙은 사전 등록·잠금(`rules_lock.json`)이고, 판단은 고정 규칙 코드가 한다. AI 가 매매를 판단한 Phil 은 68일 −2.2%, 시장보다 예측이 못했다(`docs/PHIL_ANALYSIS.md`).
2. 우리 "에이전트"는 이미 **Claude Code 세션 + Routine** 이다(매일 점검 10:00, 현황판 갱신 17:37, 한국 주식 대신 실행). 프레임워크를 하나 더 얹으면 같은 일을 두 겹으로 한다.
3. 이 저장소는 **외부 패키지 0개**(표준 라이브러리만)다. 다섯 모두 설치하면 의존성 수십 개와 **AI API 키·호출 비용**이 들어온다. 원칙 1(키를 두지 않는다)과 충돌한다.

## 2. 왜 "AI 가 매매를 판단하는 구조"로 가지 않는가 (사실 근거)

| 결과를 보고 규칙을 고치면 과최적화 — 변형 2개(risk_2·no_flag)를 결과 보고 추가한 것도 "반 걸음" | `HANDOVER.md` 3절 10/9 발견 (5) |

AI 의 자리는 **매매 밖**이다: 코드 작성, 기록 검산, 이상 보고, 문서 유지, 사람 결정 보조. 이것은 Claude Code 세션이 이미 하고 있다.

## 3. 가져올 방법 네 가지 (실행 항목)

### ① 상태 기계 + 재시작 복구 — `carrygate-exec` 주문기 (LangGraph 에서)

주문기는 15분마다 깨어나 "미체결 확인 → 포지션 확인 → 신호 → 주문"을 한다(`docs/SCALP_LIVE_TEST_PLAN.md` 4절). 집 PC 가 재부팅되거나 프로그램이 죽으면 **지금 어느 단계였는지**를 알아야 한다. LangGraph 가 "체크포인트"로 푸는 문제를 우리는 파일 하나로 푼다.

- 상태는 다섯 개뿐: `IDLE`(포지션·주문 없음) → `ENTRY_PENDING`(진입 지정가 대기) → `IN_POSITION`(보유) → `EXIT_PENDING`(청산 지정가 대기) → `IDLE`. 어느 상태에서든 안전장치가 걸리면 `HALTED`.
- 매 실행 끝에 `state.json` 에 {상태, 주문 ID, 수량, 진입가, 봉 시각} 을 쓴다. 시작할 때 이 파일과 **거래소의 실제 포지션·미체결**을 대조해, 다르면 거래소 쪽을 믿고 `HALTED` 로 간다(모르는 상태로 주문하지 않는다).
- 상태 전이는 전부 `exec_log.jsonl` 한 줄. "어떤 상태에서 어떤 입력으로 어디로 갔는지"가 남는다.
- 외부 패키지 없이 파이썬 100줄 안팎. 10/22 주문기 작성 때 이 항목을 설계에 넣는다.

### ② 역할 분담 규칙 — 모든 세션 (CrewAI 에서)

CrewAI 의 "역할을 나눈 AI 여러 개"는 Claude Code 안에서 공짜로 된다. 규칙만 정한다(`CLAUDE.md` 에 적음).

- **설계·기획·판정 해석·규칙 제안**: 세션의 최상위 모델이 직접 한다.
- **자료 수집·형식 변환·반복 검산·긴 파일 훑기**: 하위 에이전트(Agent 도구, 더 작은 모델)에 맡기고 결과만 받는다.
- 하위 에이전트에는 **목표·금지 사항·읽을 파일**을 명시해 넘긴다. 규칙 상수·`criteria.json`·`rules_lock.json` 은 하위 에이전트가 고치지 않는다.

### ③ 형식 계약 — 결과 파일 검산 + 거래소 응답 검사 (PydanticAI 에서)

- **이 저장소:** `selfcheck.py` 는 지금 **값**을 재계산해 대조한다. 여기에 **모양** 검사를 더한다 — 현황판이 읽는 결과 파일마다 "반드시 있어야 하는 키와 타입" 목록을 두고, 빠지거나 타입이 다르면 CI 빨간불. (현황판이 빈칸으로 나온 사고의 재발 방지. 표준 라이브러리만으로 가능, 패키지 추가 없음.) → 제안함에 **P14** 로 등록(규칙 변경 아님, 검산 추가).
- **주문기 `carrygate-exec`:** 거래소 응답(주문 ID·체결 수량·체결가·포지션)을 **쓰기 전에** 타입·범위를 검사하고, 하나라도 어긋나면 주문하지 않고 `HALTED`. 주문기는 별도 저장소라 `pydantic` 같은 검증 패키지를 써도 된다(원칙 1 은 키·주문을 이 저장소에 두지 않는다는 것이지 패키지 금지가 아니다).

### ④ 세션 메모리 — 루트 `CLAUDE.md` (Agno 에서)

Agno 가 파는 "메모리"는 우리에겐 문서다. 진짜 문제는 **`HANDOVER.md` 가 120KB** 라 AI 세션이 앞부분만 읽고 멈출 수 있다는 것(Phil 은 53만 바이트 문서에서 실제로 그 사고가 났다, 제안함 P7).

- Claude Code 는 저장소 루트의 `CLAUDE.md` 를 **세션 시작마다 자동으로** 읽는다. 지금까지 없었다. 이번에 만든다.
- 내용은 100줄 이내: 이 저장소가 무엇인지, 읽는 순서(`HANDOVER.md` 0절 → 5절 원칙 → `proposals.md`), 절대 규칙, 역할 분담(②), 도구 정책(이 문서), 시험 명령.
- `HANDOVER.md` 는 그대로 원본. `CLAUDE.md` 는 "어디부터 읽을지"만 알려 주는 입구다.

## 4. 앞으로 프레임워크를 "다시 검토"할 조건

아래 중 하나가 생기면 그때 1절 표를 다시 본다. 지금은 셋 다 없다.

1. **AI 가 흐름을 결정하는 단계**가 파이프라인에 들어간다 (예: 뉴스를 읽고 매매 여부를 AI 가 정함) → LangGraph·PydanticAI. 단, 그 단계도 **사전 등록·순방향 채점**을 먼저 통과해야 한다(원칙 5).
2. **AI 호출을 코드가 하고 그 출력을 코드가 읽는** 지점이 생긴다 → PydanticAI(출력 검증).
3. 현황판이 **서버가 있는 웹앱**으로 바뀐다 → Mastra.
