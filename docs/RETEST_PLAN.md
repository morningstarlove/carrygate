# 급상승·급하락 패턴 (1시간봉) 자동화 설계서

작성 2026-10-22. 출처: 사용자가 공유한 SNS 카드 4장(계정 bullcoin_, "부자들은 여기서 진입" — 급상승·급하락 패턴 그림, 캔들 용어, 블룸에너지 15분봉·팔란티어 30분봉 실전 예시).
이 문서는 그 그림을 **기계가 매일 똑같이 판정할 수 있는 규칙**으로 바꾸고, 이 저장소의 원칙(주문 없음·규칙 고정·수수료 후 성적·순방향 시험)에 맞춰 만든 기록이다.
코드: `retest.py`, 결과: `retest.json` / `retest_history.jsonl`, 시험: `tests/test_retest.py`, 판정: `verdict.py`(`criteria.json` `retest`), 제안함 P22.

> 카드의 그림(급상승 패턴): **1차 상승**(거래량 상승) → **횡보: 쉬는 구간** → **2차 상승** → **하락 조정: 투자자 익절**(거래량 감소) → 가격이 **지지 구간**(횡보 자리)으로 돌아옴
> → **상승 캔들(모닝스타)** → **매수: 롱** → 재상승. 급하락 패턴은 거울: 1차 하락 → 횡보(저항 구간) → 2차 하락 → 상승 조정 → 하락 캔들(이브닝 스타) → 매도: 숏.
> 실전 예시 두 장은 모두 "2차 상승 뒤 조정이 횡보 구간 상단까지 내려왔을 때 매수"이고, 손절은 그림에 없다(지지 구간 아래가 자연스러운 자리).

## 0. 먼저 솔직하게

- **카드에는 숫자가 하나도 없다.** "횡보"가 몇 봉인지, "조정"이 어디까지인지, "거래량 감소"가 얼마인지 전부 보는 사람 눈에 달려 있다. 우리는 그 눈을 숫자로 고정했고, 숫자는 **결과를 보기 전에** 정했다(원칙 5). 결과를 보고 고치지 않는다. 고치고 싶으면 `VARIANTS` 에 변형으로 추가해 나란히 기록한다.
- **예시 두 장은 성공한 것만 골라 보여 준 것이다.** 같은 모양이 실패한 횟수는 카드에 없다. 그래서 1년 백테스트와 순방향 기록으로 "몇 번 중 몇 번"을 직접 센다. 카드의 종목(미국 주식 15·30분봉)이 아니라 이 저장소가 이미 받는 코인 12개 시장(업비트 현물 6 + OKX 선물 6)에서 본다.
- **봉 길이는 1시간으로 정했다.** 카드는 15·30분봉인데, 코인 15분봉 규칙은 초단타 트랙에서 23일 동안 잡음으로 확인됐다(제안함 P10). 1시간봉이면 1년에 8,760봉이라 백테스트 표본이 있고, 하루 1회 실행으로도 단계 변화를 놓치는 폭이 작다. 15·30분봉으로 보고 싶으면 **새 변형이 아니라 새 트랙**이다(조합 늘리기 금지, `docs/BACKTEST_OVERFITTING_REVIEW.md`).
- 전략 자체는 고전이다. "깃발/박스 돌파 뒤 **되돌림(throwback) 에서 재진입**"으로, `patterns.py` 의 깃발형·박스권 돌파(한국 주식 트랙)에 "돌파 뒤 눌림을 기다린다"를 붙인 것이고, 추세 전환 트랙(`reversal.py`)의 "목선 돌파 뒤 눌림 진입"과 구조가 같다. 새로운 건 **지지 구간이 횡보 자리라는 것**과 **확인 캔들을 기다린다는 것** 둘뿐이다.
- 카드에 **청산(이익 실현) 규칙이 없다.** 추세 전환 트랙과 같은 연장(진입 뒤 생기는 저점마다 손절선 올리기)을 썼다. 목표가는 없다. "손절폭 2배 익절"은 변형으로만 기록한다.

## 1. 그림을 규칙으로 바꾼 것 (고정값, `retest.py` 상단)

|---|---|---|
| 봉 | 업비트 60분봉 · OKX 1H 봉. 미완성 봉 제외. 1년치 | `BAR_MIN = 60`, `DAYS = 365` |
| 고점·저점 | **피벗**: 좌우 3봉보다 높은 고가(낮은 저가). 오른쪽 3봉이 닫혀야 확정(3시간 뒤) | `PIVOT_K = 3` |

## 2. 체결·집계 가정

- 봉 단위 처리. 지정가 변형에서 체결 봉 안에 손절도 같이 나오면 순서를 알 수 없어 **건너뛴다**(횟수 `ambiguous`). 확인 봉 종가 진입은 종가가 봉의 끝이라 그 봉의 저가는 손절 대상이 아니다.
- 피벗 확정 전 3봉에 이미 횡보·돌파·조정·확인이 지나갔으면 그 봉들에 되돌려 적용한다(놓치지 않되 미래 정보는 안 쓴다 — 확정 시점에 보이는 과거 봉만).
- 같은 봉에 손절과 익절(변형)이 둘 다 걸리면 **손절을 먼저** 센다(보수적).
- 성적은 추세 전환과 같은 틀: 순수익·CAGR·최대낙폭·승률·손익비·평균 R·연도별, 최대 유리폭과 반납, 롱·숏 건수.
- 구조 통계(왜 안 들어갔나): 1차 상승 수 / 횡보 탈락(되돌림·폭·길이·거래량) / 돌파 / 2차 상승 실패 / 조정 없음(기한 만료) / 지지 깨짐 / 진입.

## 3. 실데이터 백테스트 결과

**아직 없다.** 이 세션(클라우드)은 거래소 API 가 막혀(403) 실데이터를 못 받는다. `CARRYGATE daily` 가 처음 돌면(또는 Run workflow → `dry_run`) `retest.json` 에 1년 백테스트가 생기고, 그 표를 인수인계서 마일스톤 16 에 옮겨 적는다.
가짜 봉(무작위 걸음 1년 × 12시장)으로는 기본 규칙이 **1년에 0~1건**, `no_vol` 이 164~347건이었다 — 거래량 조건 3개가 대부분을 거른다. 실데이터에서도 매매가 너무 적으면(연 20건 미만) 판정이 오래 "판단 전"에 머문다. 그래도 규칙은 고치지 않고, 변형 `no_vol` 의 기록과 나란히 본다.

## 4. 매일 하는 일

- `CARRYGATE daily` 워크플로에서 추세 전환 다음에 `python retest.py` 가 돈다. 12개 시장 1시간봉 1년치를 받아(OKX 100개씩 88번, 업비트 200개씩 44번) 백테스트를 다시 하고, 오늘 단계와 가격을 기록한다.
- 단계: `scan` 대기 / `box` 횡보 중(상단·하단) / `rise2` 돌파 확인, 2차 고점 대기 / `pullback` **조정 중 — 지지 구간 x~y 에서 확인 봉이 닫히면 진입, 손절 z** / `long`·`short` 보유(손절선).
- 하루 1회 실행이라 1시간봉 24개 중 **마지막 완성 봉 기준**의 상태만 남는다. 확인 봉은 하루 안에 생기고 지나갈 수 있다 — 이 저장소는 판단만 기록한다(원칙 1). 실전에서 쓰려면 1시간마다 봐야 한다(5절).
- `python retest.py --report` 로 단계 변화를 본다. 검산(`selfcheck.py check_retest`)이 실현 순수익 재계산·손절선 방향·손절 체결가·진입가 위치를 대조한다.

## 5. 합격선과 다음 단계 (사전 등록, `criteria.json retest`)

| 항목 | 값 | 이유 |
|---|---|---|
| 판단 최소 건수 | 거래소별 순방향 **20건** | 추세 전환과 같음. 20건 전에는 판단하지 않는다 |
| 합격(PASS) | 손익비 ≥ **1.5** | 소액 실전 설계 후보 |
| 불합격(FAIL) | 손익비 < **1.0** | 규칙은 고치지 않고 "이 규칙은 안 된다"로 기록 |
| 경고 | 운 보정 z < −2 | 백테스트 승률대로면 나올 승수와 어긋남 |

**합격 뒤 "진입 할 수 있게" 하는 길** (이 저장소 밖, 원칙 1):
1. `retest.json` 의 `signal` 이 이미 진입 계획을 다 적는다 — 지지 구간(`zone_lo`~`zone_hi`), 손절(`stop`), 확인 봉 규칙, 지지 상단 체결 가정 수량(`units_if_fill_at_zone_edge`)·명목 비율. 사람이 보고 1시간봉 마감마다 확인 봉이 닫혔는지 보면 된다.
2. 자동화는 별도 저장소 `carrygate-exec`(`docs/SCALP_LIVE_TEST_PLAN.md` 4절)에서 **1시간마다** `retest.run` 을 돌려 `pullback` 단계 시장의 확인 봉을 보고 지정가·시장가를 낸다. 사용자 가상서버(Vultr 서울, `docs/VPS_SETUP.md`)가 그 24시간 컴퓨터가 된다. 바이낸스로 옮기려면 봉만 바이낸스 1H 로 바꾸면 된다(규칙 동일).
3. 그 전에 반드시: 순방향 20건 PASS → 소액 체결 시험 설계서 사전 등록(합격선 6개, P13 틀) → 2주 → 실전 규모는 MinTRL(판정 파일 `interpretation.min_trades_95`) 이후.

## 6. 바꾸고 싶을 때

규칙 상수는 `rules_lock.json` 에 잠겨 있다. 바꾸려면 `proposals.md` 에 근거 → `RULE_FIXED` 새 날짜 → `python verdict.py --lock`. 변형 추가는 `VARIANTS` 에 추가만. 15·30분봉은 변형이 아니라 **새 트랙**으로(조합 늘리기 금지).
