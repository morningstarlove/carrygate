## 1. Phil 이 무엇인가

- Claude Code 가 가상 1,000달러로 **Polymarket(예측 시장)** 에 모의 베팅을 한다. 스포츠·경제지표·뉴스·선거 등 단기 시장.
- 1~2시간마다 한 사이클: 결과 정산 → 성적 채점 → 반성문(retro) 작성 → **자기 전략 파일(`strategy/`)을 고쳐 git 커밋** → 시장 스캔(300개) → 조사 → 베팅.
- 사람(운영자)은 엔진(`core/`, `config/`)만 소유. AI 는 엔진을 못 고치고, CI 가 이를 자동 검사한다.
- 핵심 지표는 손익이 아니라 **Brier delta**: "AI 의 확률 예측이 시장 가격보다 더 정확했나".

## 4. 그래도 가져올 가치 — "방법"

carrygate 는 이미 종이매매 기록(초단타·터틀·추세전환·한국주식 돌파)을 쌓고 있지만, **"기록을 보고 전략을 어떻게 고칠지"의 규율이 없다**
(원칙 5: 사후에 문턱값을 손대면 과최적화). Phil 은 바로 그 문제를 푸는 구조를 갖고 있다.

| Phil 의 장치 | 뜻 | carrygate 에 이식하면 |
|---|---|---|
| 보호 엔진 / 편집 가능 전략 분리 + CI 경계 검사 | AI 가 채점기·캡은 못 건드림 | 채점·수수료·원장 코드는 보호, 규칙 변형만 AI 가 제안 |
| 시장 대비 Brier (`brier_delta`) | "내 예측이 가격보다 나은가"가 유일한 성적 | 종이매매 승률 대신 **대조군 대비 성적**(이미 `kr_backtest` 에 no_sector 대조군 있음)을 정식 지표로 |
| 운 보정 z 점수 | 운 vs 실력 분리 | 순방향 20~100건 뒤 판정할 때 그대로 쓸 수 있음 |
| 사전 등록(pre-registration) + 순방향 검증 + 봉인 컷오프 | 규칙을 바꾸기 전에 기준을 먼저 적고, 바꾼 뒤 새 데이터로만 판정 | 원칙 5 를 **"바꾸지 마라"에서 "바꾸려면 이 절차로"** 로 발전 |
| 정산마다 반성문 → 전략 파일 수정 → 커밋 | 학습이 git 이력으로 남음 | 매일 자동 실행 뒤 "오늘 정산 건 반성문" 1개 자동 생성 |
| `proposals.md` (AI → 운영자 제안함) | 엔진 변경은 제안만 | 지금 인수인계서의 "미뤄 둔 것"을 제안함으로 구조화 |
| 변형 나란히 기록 (Phil 의 policy replay) | 믿음은 고정, 결정 규칙만 바꿔 재채점 | carrygate 의 `VARIANTS`(base/no_sector/hold_10/risk_2) 와 같은 발상 — 이미 하고 있음 |

**교훈 하나 더:** Phil 은 전략 문서가 53만 바이트(8,400줄)까지 부풀어 AI 가 앞 2,000줄만 읽는 사고가 났다.
carrygate 인수인계서(85KB)도 같은 길을 가고 있다. 섹션 지도 + 보관함(archive) 분리가 필요하다.
