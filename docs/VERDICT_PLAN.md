2. 승률만 보면 운과 실력을 못 가른다 → **백테스트 기대 승수 대비 z** 로 운을 보정한다.
3. AI 든 사람이든 규칙을 슬쩍 고친다 → **잠금 + CI** 로 기계가 막는다.

## 2. 판정 기준 (봉인 2026-10-06, `criteria.json` 이 원본)

| 트랙 | 최소 건수 | 합격 | 불합격 | 출처 |
|---|---|---|---|---|
| 한국주식 돌파 (base) | 15건 | 승률 ≥ 20% 이고 손절 매매 깊이 정상(−9.5% 보다 깊은 손절 ≤ 1건) | 승률 < 15%, 또는 20일 보유 매매(5건 이상)의 승 비율 < 60% | 인수인계서 마일스톤 12-4 기준 4개 |
| 추세전환 (거래소별) | 20건 | 손익비 ≥ 1.5 | 손익비 < 1.0 | `docs/REVERSAL_4H_PLAN.md` 5절 |
| 터틀 (거래소별) | 20건 | 손익비 ≥ 1.2 이고 운 보정 z ≥ −2 | 손익비 < 1.0, 또는 z < −2 | 인수인계서 마일스톤 10 (20건 전 판단 금지) + **이 세션이 봉인한 합격선 → 제안함 P6, 사용자 확인 필요** |
| 초단타 | 7일 | 견고 조합 ≥ 1 | 7일 이상인데 견고 조합 0 | `scalp.py` 자체 규칙 |

- 사이에 있으면(예: 돌파 승률 15~20%) NOT_YET 으로 두고 더 모은다.
- 거래소별 트랙은 **한 거래소라도 FAIL 이면 전체 FAIL**, 모두 PASS 여야 PASS.
- 대조군(돌파의 `no_sector`), 변형(터틀 `s2_55_20`·`ch_22_3`, 추세전환 `no_vol`·`break_entry`) 은 **기록만** 한다. 합격선에 안 쓴다.

## 3. 운 보정 z 읽는 법

백테스트 승률 p 로 n 번 매매하면 기대 승수는 n×p, 표준편차는 √(n·p·(1−p)).
z = (실제 승수 − 기대 승수) ÷ 표준편차.

- z ≈ 0: 백테스트와 같은 실력. 
- z < −2: 20번에 한 번 나올 불운 — 그보다는 **백테스트가 부풀려졌다**(생존 편향·과최적화)고 본다. Phil 은 z = −3.75 였다.
- 돌파 트랙은 백테스트 승률 28.9%, 터틀 업비트 37.8% / OKX 34.6%, 추세전환 업비트 37.1% / OKX 34.4% 가 기준이다.

## 4. 규칙을 바꾸고 싶을 때 (사전 등록 절차)

```
1. proposals.md 에 번호·근거·기대 효과를 적는다
2. 그 트랙의 RULE_FIXED 를 새 날짜로 잡는다  (그날부터 순방향을 새로 센다)
3. python verdict.py --lock                  (rules_lock.json 재생성)
4. 셋을 한 PR 로 올린다. CI 의 tests.test_verdict 가 통과해야 합쳐진다
```

이 순서 없이 상수를 고치면 `test_lock_matches_source` 가 어느 값이 바뀌었는지 짚어 실패한다.
변형을 **추가**하는 것도 잠금에 잡힌다(VARIANTS 가 규칙 사전에 들어 있다) — 추가는 허용이지만 같은 절차로 기록을 남긴다.

## 5. 매일 보는 법

```
python verdict.py            # 지금 판정 (Actions 로그 "Verdict" 단계에도 찍힌다)

```

`verdict.json` → `summary` 네 줄이 전부다. 통합 현황판에 카드로 붙일 때 이 넷을 읽는다.
